Why Janus-Ops

Stop juggling six tools to run one infrastructure.

Checkmk for monitoring, Portainer for containers, the Proxmox web UI, MobaXterm for SSH, a terminal for Ansible. Every jump costs context. Janus-Ops, named after the two-faced Roman god of gateways, puts one central inventory at the core: define a host once and its capabilities (agent, SSH target, Docker host, Proxmox node, SNMP device) light up the matching tools.

One inventory

Nodes, tags, groups with Ansible variables, parents for alert suppression, and a vault for every credential.

Built for restricted networks

Segmented, proxy-only and air-gapped sites are the design target. The UI ships every asset locally, with no CDN and no fonts fetched from the internet.

Auditable by default

Every privileged action is attributed and written to a hash-chained audit log, with optional terminal session recording.

Modules

Everything an operator reaches for, in one place.

Each module is useful on its own and gets better with the others: a failing check can open the container logs, the SSH session or an Ansible run on the same host.

Observability & alerting

High-frequency metrics, service discovery, OK / WARN / CRIT / UNKNOWN with hysteresis, acknowledgements, downtimes, flapping detection, parent/child dependencies and notification routing. SNMP v2c/v3 for NAS, switches and UPS, with check templates built from an OID catalog, v2c traps and MIB names. Charts from 5 minutes to 90 days.

Checkmk-style

Containers & stacks

Multi-host Docker through the agent tunnel: live logs and stats, exec shells, Compose stacks deployed from Git with signed webhooks, prune and image update checks.

Portainer / Dockhand-style

Virtualization

Proxmox VE clusters: quorum, nodes, storage, VM and LXC lifecycle, snapshots, migration, console, plus backup and replication audit.

Proxmox VE

SSH bastion

A web terminal with host key pinning, vault-backed credentials, an SFTP browser, multi-tab and broadcast, a snippet library, ProxyJump, and session recording.

MobaXterm / Termius-style

Automation hub

Ansible playbooks with a dynamic inventory from the database, surveys and live output. A visual workflow builder with webhook, interval and alert triggers, branches and approvals, and management steps: restart a service, container or Proxmox guest, check a process, an HTTP page or a port, wait, retry and verify. Steps that change something wait for a person unless you decide otherwise, and runs resume after a restart.

AWX / n8n-style

AI Copilot & Operate

Root-cause analysis that can look at the node itself through MCP tools, knowing which hypervisor a VM runs on, a second opinion from another model, contextual IaC generation, and a chat to carry out an instruction on the servers you pick. Providers and keys of your choice, each added from a gallery with its address filled in, with fallback routes when one fails and the main and second-opinion models picked from a list. Plans wait for approval; changes need a dedicated permission and are audited call by call.

Any OpenAI-compatible provider

Backup & restore

Export the whole configuration (hosts, checks, notifications, workflows, AI providers) to one file, with the secrets encrypted by a passphrase you choose. Import it back with a preview first, into the same or another installation.

Preview before you apply

Archive & retention

Recorded SSH sessions and Operate chats move to a searchable archive after a number of days and are deleted after another. Search even inside the recorded output, filter by host or group, replay, and mark what must never be deleted.

You set the days

Access, roles & audit

Sign-in against an LDAP directory, two-factor authentication, roles with fine-grained permissions (reading a stored secret has its own), per-group scoping and an audit log of who did what, from where.

Least privilege by default

The agent

A single Go binary that only ever calls out.

No inbound port on your nodes, no dependency to install. janus-agent opens one outbound WebSocket over HTTPS and everything else (telemetry, Docker, commands, updates) travels through it.

your node

  • janus-agent, static binary
  • Linux amd64 · arm64 · arm (Raspberry Pi)
  • Windows service, installed with one PowerShell line
  • 24 h disk buffer while offline
outbound only
TLS · port 443

janus-ops server

  • Ed25519 key per agent, one-time enrollment token
  • Optional HTTP(S) proxy
  • Signed self-update, with automatic rollback
  • Everything audited
  • You keep the last word. Whether a node accepts commands, interactive shells or the Docker API is a local policy written when the agent is installed. The server cannot change it afterwards.
  • Install your way. Over SSH from the UI, or with a one-line PowerShell command on Windows when SSH is not an option.
  • Updates you can trust. Releases are signed offline with an Ed25519 key; the agent verifies the signature, refuses downgrades and rolls back if the new binary does not come up.
Security

Secrets stay on the server. Actions stay attributable.

Encrypted vault

Envelope encryption with AES-256-GCM, one key per secret. Secrets are write-only: no page or API returns them and they never reach the audit log. The one exception is a Show button for users you grant a dedicated permission: it opens the secret for 30 seconds and records every view first. The master key or the secrets themselves can live in an external manager such as OpenBao or HashiCorp Vault.

Identity and access

LDAP-backed sign-in (lldap included, or your own AD/LDAP), optional TOTP, a break-glass account, and RBAC with Admin, Operator and Auditor roles plus custom roles and per-node scope.

Immutable audit trail

Every sign-in, change, shell, restart, playbook and AI action plan is attributed and chained by hash, so tampering is detectable.

Human in the loop

The AI Copilot is read-only by default, never sees vault secrets and never runs destructive actions on its own. Plans wait for approval from someone with the right permission.

Quick start

From clone to console in a few commands.

You need Docker with Compose v2, make and a Linux host. The stack runs a TLS proxy, the app, TimescaleDB and an LDAP directory.

# from a clone of the repository
$ git clone https://github.com/lordraw77/janus-ops && cd janus-ops
$ make env          # creates deploy/.env with random secrets
$ make docker/run   # builds the image and starts the stack

# then open https://localhost/ and sign in as janus-admin
# (the initial password is JANUS_ADMIN_PASSWORD in deploy/.env)

Prefer the published image? See the Docker Hub overview, or read the full guide on GitHub.
